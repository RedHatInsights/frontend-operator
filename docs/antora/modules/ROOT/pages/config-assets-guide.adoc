= Publishing Generated Configuration

The frontend operator can also publish its generated base configuration to S3 through the existing valpop/push cache integration. Enable it on a `FrontendEnvironment`:

[source,yaml]
----
spec:
  enablePushCache: true
  valpopImage: quay.io/redhat-services-prod/hcc-platex-services-tenant/valpop:latest
----

Pin `valpopImage` to a tested release or digest for deployment. The image must provide `valpop populate`, `--cache-max-age`, `--valpop-image`, and `--secure`, plus `/bin/sh` and `cp` for staging the files.

`enablePushCache` controls both frontend assets and generated configuration. Configuration uploads continue when `disableContainerDeployments` is enabled. A Frontend must reference the environment to trigger reconciliation.

== Files and storage

The publisher uploads the following generated files, reusing the same reconciliation output as the environment's base and locale ConfigMaps:

* `fed-modules.json` (required): the operator-generated module registry.
* `bundles.json`
* `search-index.json`
* `api-specs.json`
* `service-tiles.json`
* `sso-config.json`
* `exports.json`
* `locales.json`: enabled locales, including relative message filenames for non-English locales.
* `messages.<locale>.json`: every generated locale catalog, including translations staged before a locale is enabled.

[cols="1,2,2",options="header"]
|===
| File | Contract | Producer and consumer
| Per-application `fed-mods.json`
| Module-federation build manifest describing the application's loadable assets. Its URL is the registry entry's `manifestLocation`.
| Produced by the application's build tooling; consumed by the frontend module loader.
| Aggregate `fed-modules.json`
| Object keyed by application name, with `FedModule` entries (`manifestLocation`, `modules`, `config`, and other CRD-defined fields).
| Generated by FEO from Frontend resources. Used by Chrome's operator-generated configuration path and as input to the Chrome service's configuration processing. This publisher copies its bytes to `data/config/fed-modules.json`.
| Processed `fed-modules-generated.json`
| Application registry after merging the FEO entries with legacy static configuration; FEO entries override matching application keys.
| Produced by `chrome-service-backend` configuration processing and consumed by Chrome through `/api/chrome-service/v1/static/fed-modules-generated.json`. It is not generated by this publisher.
|===

The publisher does not merge legacy configuration or change consumer URLs. Enabling it preserves the existing Chrome mount at `/srv/dist/operator-generated/fed-modules.json` and its public `/apps/chrome/operator-generated/fed-modules.json` path while Chrome deployments remain enabled. Turning on `disableContainerDeployments` removes those deployments and is a separate rollout decision: any consumer still using the legacy path needs routing or consumer changes first. The object-storage prefix is not an alias for that public URL.

The Caddyfile and widget/layout ConfigMaps remain excluded. Every non-English message file referenced by `locales.json` must be present in the publication payload. Translation-only changes participate in the upload identity but stay outside the frontend deployment hash. Changes only to excluded files do not trigger an upload.

Disabling a locale removes it from `locales.json`, not necessarily from object storage. Generated translations may remain staged, and previously uploaded files follow the existing retention policy. Consumers must use the enabled-locale manifest rather than infer availability from stored filenames.

Valpop uses prefix `config`, placing files under `data/config/<filename>` in the configured bucket. JSON objects receive `Cache-Control: public, max-age=60`. Bucket access policy, CDN routing, and switching consumers to these URLs are configured separately. Environments that require isolation must use separate buckets; the `config` prefix is shared within a bucket.

Credentials and destination use the existing push cache configuration, including Secret references. The Job contains `secretKeyRef` environment variables, not literal credentials. For local development, the operator can read the `env-<namespace>-minio` Secret used by existing push cache tests.

== Serving locale assets and changing storage

The frontend-asset-proxy maps `GET /config/locales.json` to `data/config/locales.json` in its configured bucket, and `/config/messages.fr.json` to `data/config/messages.fr.json`. Relative manifest filenames resolve under the same `/config/` base URL, and `/apps/config/` is an alias for the same objects. GET and HEAD use the same mapping. A missing config object returns an error, never SPA HTML, so Chrome can fall back to English. That last guarantee, and HEAD on the `/apps/` alias, need a proxy image that includes the RHCLOUD-53795 change; older images answer missing config with the SPA entrypoint.

FEO runs this proxy when `enablePushCache` and `reverseProxyImage` are both set, in the namespace named after the environment. It configures the proxy from the same object-store settings as the publisher: bucket, region, Secret-referenced credentials, and an upstream URL built from the endpoint and port. The upstream scheme is `https` only for port 443; FEO does not read the TLS setting for it.

Configure console edge routing to send the selected public config prefix to the asset proxy. Publishing objects alone does not establish that route or switch Chrome to it. The public hostname and routing are deployment decisions; enabling publication changes no production routing.

Keep this URL contract and object layout when moving between S3-compatible backends. Change only the existing object-store endpoint, port, bucket, region and credential Secret; the publisher and the proxy both pick them up. For AWS:

* Use the bucket's regional endpoint (`s3.<region>.amazonaws.com`) on port 443. Valpop then connects with TLS (`--secure=true`) and the proxy with `https`.
* Valpop creates its S3 (minio-go) client without a region, so the client looks the bucket region up itself. Grant its principal `s3:GetBucketLocation` in addition to the existing list, read, write and cleanup permissions.
* The proxy signs for the configured region and sends path-style requests to the explicit endpoint.
* A standalone proxy can also take an explicitly empty `MINIO_UPSTREAM_URL` to use AWS SDK regional endpoint resolution. FEO always sets an explicit endpoint.

Do not use local test credentials in AWS. These settings were checked against the valpop and proxy sources and the MinIO integration test, not against live AWS. Bucket provisioning, data copy, permissions and the production cutover are separate operational work. Public URLs need not change when only their storage origin changes.

== Upload lifecycle

There is one config upload Job per environment and namespace. After generated ConfigMaps have been saved, the operator creates an immutable snapshot containing exactly the selected files. Large payloads are split into ConfigMaps below the 1 MiB API limit and projected into the same Job volume. Each part has an upload-specific label for cleanup, including recovery when replacement of an immutable part is interrupted. An init container copies the projected files into an `emptyDir`, so valpop reads regular files rather than Kubernetes ConfigMap symlinks.

The upload identity includes the filenames and contents, destination, and cache policy. A configuration change therefore uploads even when the frontend and valpop images stay the same. An unchanged completed Job is retained without another upload. Changing `valpopImage` replaces the Job, although valpop can still skip uploading unchanged content.

The operator waits for foreground deletion of the previous Job and its pods before replacing the snapshot. Failed Jobs are reported through the existing Frontend reconciliation error and retried. Publication runs after generated resources have been applied and obsolete Frontend resources have been pruned, so upload errors cannot block that cleanup. Each Job has a five-minute deadline and a backoff limit of three. Pending Jobs are checked every ten seconds.

Setting `enablePushCache: false` removes the upload Job and snapshot on reconciliation. It does not remove uploaded S3 objects. Files removed from the generated inventory follow valpop's retention/cleanup behavior (`minAssetRecords`, default 3, and a 48-hour retention timeout); they are not guaranteed to disappear immediately. Uploads overwrite individual object keys, so this mechanism does not provide an atomic switch of all configuration files or a transactional rollback.

The operator also removes the Job and snapshot when the last Frontend in that namespace is deleted. Shared resources remain while another Frontend in the same namespace references the environment. Frontend finalization waits for the uploader's foreground deletion before releasing its snapshot.

Changing a Frontend's `envName` does not scan or prune uploads from its previous environment. Those resources remain owned by that environment and are garbage-collected when it is deleted, or cleaned up if publication is disabled and another Frontend reconciles there.
